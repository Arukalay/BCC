# ИИ-валидатор требований (`validator`)

Статический ИИ-агент для автоматизированного ревью документов требований до начала разработки (хакатон **BCC-HUB x MNU FinTech**). Агент проверяет требования по критериям **ISO/IEC/IEEE 29148:2018** (п. 5.2.5, 5.2.6) и **IEEE Std 830-1998** (п. 4.3), находит двусмысленности, противоречия, непроверяемые формулировки, пробелы, навязанные проектные решения и нарушения шаблона, после чего формирует структурированный отчёт в формате Markdown на русском языке.

---

## 1. Требования

- **Python 3.11+**
- **Git** (для автоматического определения версии агента в паспорте отчёта)
- Доступ в интернет и бесплатный API-ключ **Google Gemini API**

---

## 2. Установка

Клонируйте репозиторий, создайте виртуальное окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate        # для macOS / Linux
# .venv\Scripts\activate         # для Windows

pip install --upgrade pip
pip install -r requirements.txt
```

Если в папке `docs/` ещё нет файла задания организаторов, скачайте исходный `docs/requirements.md` из репозитория задачи (не изменяйте его!):

```bash
curl -sL https://raw.githubusercontent.com/BCC-HUB/ai-requirements-validator-task/main/docs/requirements.md -o docs/requirements.md
```

---

## 3. Как получить API-ключ Gemini

1. Перейдите в Google AI Studio: <https://aistudio.google.com/>
2. Войдите под учётной записью Google и нажмите **Get API key** → **Create API key**.
3. Скопируйте сгенерированный ключ.

---

## 4. Настройка окружения

Создайте локальный файл `.env` на основе шаблона `.env.example`:

```bash
cp .env.example .env
```

Откройте `.env` и заполните параметры:

```env
GEMINI_API_KEY=ваш_ключ_из_ai_studio
GEMINI_MODEL=gemini-2.5-flash
LLM_PROVIDER=gemini
```

> **Важно:** файл `.env` добавлен в `.gitignore`. Никогда не коммитьте `.env` и свои API-ключи в репозиторий.

---

## 5. Запуск

### Проверка подключения к модели и доступных моделей на ключе
```bash
python -m validator --check-llm
```

### Анализ документа требований
Поддерживаются входные форматы: `.md`, `.txt`, `.pdf` (с текстовым слоем), `.docx`.

```bash
python -m validator docs/requirements.md report.md
```

Дополнительные опции:
- `--verbose` / `-v` — подробное логирование шагов, ретраев и диагностики в `stderr`.

---

## 6. Куда ложится отчёт и что в нём

Итоговый отчёт сохраняется по пути, переданному вторым аргументом CLI (например, `report.md`). Если целевая директория не существует, агент создаст её автоматически.

Структура отчёта на русском языке:
1. **Паспорт прогона:** имя входного файла, дата и время запуска (ISO), модель LLM, версия агента (короткий хеш коммита `git`).
2. **Таблица нарезки требований:** `ID в отчёте` (`R-01`, …) — `ID в документе` (`Ф-1`, `НФТ`, …) — краткая формулировка.
3. **Проверка каждого требования:** выявленные нарушения критериев качества с критичностью (`critical` / `major` / `minor`), дословной цитатой из документа и рекомендацией по исправлению.
4. **Проверка набора требований целиком:** межтребовательные противоречия, пробелы, несогласованность терминов и нарушения шаблона.
5. **Сводка:** детерминированный подсчёт числа требований, нарушений и список критичных дефектов.
6. **Итог:** вывод о готовности документа к разработке/тестированию и приоритеты доработки.

---

## 7. Какая модель использована и почему

По умолчанию используется **`gemini-2.5-flash`** (устаревшая `gemini-1.5-flash` заменена):
- Доступна на бесплатном тарифе Google AI Studio.
- Нативно поддерживает **Structured Outputs** (`response_mime_type="application/json"` + `response_schema`), что гарантирует строгое соответствие ответов Pydantic-схемам (`validator/schemas.py`).
- Высокая скорость отклика и большое контекстное окно позволяют анализировать многостраничные спецификации за минимальное число запросов.

Архитектура клиента (`validator/llm.py`) изолирована через абстрактный интерфейс `LLMClient`, что позволяет при необходимости подменить провайдера через `LLM_PROVIDER`.

---

## 8. Логи и запуск тестов

- **Логи:** выводятся в `stderr`. Для детальной трассировки запросов, ретраев и размеров документа запускайте с флагом `--verbose`:
  ```bash
  python -m validator docs/requirements.md report.md --verbose
  ```
- **Тесты:** запускаются через `pytest`:
  ```bash
  pytest -v
  ```

---

## 9. Ограничения и известные проблемы

- **Лимиты бесплатного тарифа Gemini API:** на бесплатном уровне действуют ограничения на число запросов в минуту (**RPM**, обычно ~10 запросов/мин для `gemini-2.5-flash`) и запросов в день (**RPD**, ~250 запросов/день). В `validator/llm.py` реализованы автоматические повторы с нарастающей паузой (`2, 5, 15, 30` сек) при ошибках `429` и `5xx`.
- **Сканированные PDF:** модуль `validator/loader.py` извлекает текстовый слой через `pypdf`. Если PDF состоит только из изображений без текстового слоя, агент выдаст ошибку с подсказкой о необходимости предварительного OCR.
- **Сверка цитат:** проверка дословных цитат опирается на функцию `validator.loader.normalize()`, которая унифицирует пробелы, кавычки и тире.
